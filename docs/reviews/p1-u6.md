# Review: P1 unit 6, the app screens

This is the reviewer's pass over `60be415` (`rv-p1-u6`). The branch also carries unit 3's protocol commits, so the unit's own change is `239d82c`, `347755d`, `feb5d05` and `5c7a58f`: `crates/app`, `client/src/host_view.rs`, `client/src/new_session.rs`, the CSS and the screenshots. The contract is `docs/p1/design.md` §3, §5 (unit 6's row), §6 and §8, under subset version 6. I read the friction log (`.audit/p1-u6.friction.md`) and the 18 screenshots in `docs/p1/screens/`.

Every rewrite below was applied to a scratch copy of `60be415`, and `cargo clippy -p app -p client --all-targets -D warnings` and `subset check` passed on each one. Proposal 3 changes `proto`, so `daemon` was not built for it. The patches are in `docs/subset/measurements/p1-u6/`, and `measure.sh` there applies them in order and reprints every token count in this review.

The verdict is **accept after the required fixes**: six code fixes (fix 4 depends on the owner's gap-1 decision), the gap-2 change and four accessibility fixes. With the fixes, the three screen files go from 5,079 to 4,767 tokens, and the app crate from 6,908 to 5,440. The screen files then stand at +49% against the 3,200 budget. That remainder is the budget's error, not avoidable code (Volume, below). The fixture should be deleted rather than kept behind a flag. There are no subset proposals. One finding is for the owner's decision on 0040, which is open on `rv-p1-u3`.

**The qualities.** These hold except where a required fix names a breach.

- **Named states.** `Screen`, `Link`, `Opening`, `Attempt`, `Refusal`, `Availability`, `Attention` and the local `Start` replace what would otherwise be flags. `rsx!` bodies still pass DOM booleans (`disabled`, `checked`, `aria-current`), which is a library boundary under 0023.

- **One way, Repetition is data.** These are breached twice. The status words are matched in two components, and the provider availability is computed and matched twice in one loop (required fixes 1 and 2).

### Required fixes

Each saving is the token change on the files named, measured with the earlier fixes applied (`measure.sh`).

1. **One status word, used by both the row and the pane.** This fixes friction 7 within v6. `SessionPane` and `SessionRow` each match `SessionStatus` into a `("running", String::from("Running"))` pair and then call `.to_lowercase()` on the text. The text is always the attribute value, so one word serves both. Add this to `host_view.rs`:

   ```rust
   impl SessionStatus {
       /// The status in one word, for the UI's text and its `data-status`.
       pub fn word(&self) -> String {
           String::from(match self {
               SessionStatus::Starting => "starting",
               SessionStatus::Idle => "idle",
               SessionStatus::Running => "running",
               SessionStatus::Closed(_) => "closed",
           })
       }
   }
   ```

   The pane uses `"data-status": "{status}"` and `"{provider}, {status}"`. The row's two matches (status and badge) become one match on `attention()` that returns `(status, text, badge)`, with `session.status.word()` in the `Quiet` arm. The change is −58 in `SessionRow`, −69 in `session.rs` and +55 in `host_view.rs`, so **−72 tokens**. The saving is small. The breach is quality 7, two places sharing one shape, and that is why the fix is required.

2. **One availability decision per provider segment.** `NewSession` calls `form.read().availability(&host, choice)` twice per segment and matches it twice, once for `data-available` and once for the text. The fix is to map each choice to one word before the loop, as in `for (choice, state) in PROVIDERS.iter().map(|choice| (*choice, ..word()))`, and use `"{state}"` for both. In CSS, add `text-transform: capitalize` to `.segment-state` and hide `[data-available="unknown"] .segment-state`. The change is **−4 tokens** net (−51 in `NewSession`, +47 for the word function). With fix 4, the word function moves into `sessions.rs` over `proto::Availability`. This fix is about quality 6 (one way), not volume.

3. **Delete the fixture** (The fixture, below). This deletes `fixture.rs`, `Link::Fixture` and its arm in `send`, `Opening::Fixture` with its arm in `App`, the `#fixture` and `CONDUCTOR_FIXTURE` branches in `ticket::initial`, and `Shell`. `Shell` exists only so that `Host` and `Fixture` can share the screens, so its body goes back into `Host`. That is −1,100 (`fixture.rs`), −92 (`main.rs`), −56 (`ticket.rs`) and +2 (`sessions.rs`), so **−1,246 tokens** in total and −146 outside the fixture file.

4. **Provider availability from `Welcome`**, if the owner accepts gap 1 as specified below. `new_session.rs` shrinks to `PROVIDERS`, `label`, `Attempt`, `Refusal` and `Attempt::answered`, from 938 to 377 tokens. The rest of the change is `sessions.rs` +45, `main.rs` +18, `link.rs` +25 and `proto/src/lib.rs` +104. That is **−416 tokens measured**, plus about −38 in `daemon` (estimated: `Providers` and its `Availability` move out of `registry.rs`, and `Providers::of` replaces `start`'s match).

5. **`submit` as one exhaustive match.** This removes friction 5 within v6. The friction-log form lifts a `bool` into an `Option` so that `if let` can test it, which hides the "empty" and "busy" cases. A literal pattern already covers "empty", as `NewSession`'s `(_, "") => Start::Empty` does:

   ```rust
   match (composer, draft().trim()) {
       (Composer::Open, "") | (Composer::Busy | Composer::Closed, _) => {}
       (Composer::Open, text) => {
           on_send(text.to_string());
           draft.set(String::new());
       }
   }
   ```

   The score goes from 103.5 to 84.5 (**−18%**), and the token count from 84 to 97 (+13). Every case is now a visible arm (quality 2).

6. **The two icons move from `rsx!` into CSS.** The back chevron in `PaneHeader` and the send arrow in `Composer` are inline `svg { path { .. } }` blocks of 43 tokens each, at the costly `rsx!` weight. Each becomes an empty element whose shape is a CSS `mask-image` with a data-URI SVG and `background-color: currentColor`. That saves **−86 tokens**. The patch removes the markup only, and the implementer writes the two CSS rules.

With fixes 1 to 6 and the gap-2 change below, the screen files are 4,767 tokens and the app crate's five files are 5,440. That is −1,468 against 6,908.

## The fixture

The fixture puts 1,100 tokens of invented sessions into every user's bundle, plus 146 tokens of plumbing to reach them. Here are the options, measured or counted.

- **(a) `cfg(feature = "fixture")`, scoped to `crates/app`.** Rejected. A feature predicate is not enough on its own. The fixture is reached through an enum variant (`Link::Fixture`), a match arm in `send`, another variant (`Opening::Fixture`) and its arm in `App`, and one branch in each `initial`. None of those are items, so 0016's rule ("on items, each with its counterpart") can't gate them. Gating them needs `cfg` on variants and arms, and `all(not(target_family = "wasm"), feature = "fixture")` combinations. That is seven sites of about 10 tokens each at the tolerated weight, or about +70 tokens over (c). It also keeps all 1,100 tokens in `crates/` and adds a build mode that `tools/check.sh` doesn't cover.
- **(b) An example target or a `tests-e2e` web build.** This works, but costs more than it saves. An example is its own crate root, so it needs `crates/app/src/lib.rs` to reach the screens. It also needs 0018's `attr.allow` scope widened from `main.rs` to `lib.rs`, the components made `pub`, and `Link::Fixture` kept in the shipped library so that the example can answer commands. Without that variant the new-session screenshot only shows "Not connected".
- **(c) Keep it shipped.** Rejected, because it ships fake data to users.
- **(d) Delete it, and take the screenshots from the real host on the fake CLIs.** Recommended. This is −1,246 tokens (required fix 3), and nothing replaces it in `crates/`. §5 already asks for the screenshots against a real host. Unit 1's gated fake CLI holds a turn at an open permission, which gives the approval screen, and holds it mid-stream, which gives the running screen. Unit 7's `browser.mjs` drives the real daemon on those fakes. A host with no `codex` on its `PATH` gives the "Codex unavailable" refusal through the registry's permanent path. `tools/app-screens.mjs` becomes a scenario in unit 7. Until then, the committed screenshots stand.

## Gaps

### 1. Provider availability (the owner is deciding)

I recommend the `Welcome` field. Availability is fixed when the host starts (`registry.rs`: "Built once in `main`"), so it belongs with the other per-connection facts, not in the event log. Today a phone user learns that Codex is missing only after choosing it, typing a path and tapping Start. With the field, the form shows "Unavailable" before any of that. The client stops inferring availability from past sessions and refusals, which is where `new_session.rs`'s 938 tokens come from (required fix 4).

The exact change, as measured in `3-providers-in-welcome.patch`:

- **`proto`.** `Welcome` gains `pub providers: Providers`. `Providers { pub claude: Availability, pub codex: Availability }` and `enum Availability { Available, Unavailable { reason: String } }` move here from `daemon/src/registry.rs`, with serde derives. Add `impl Providers { pub fn of(&self, provider: Provider) -> &Availability }`, which is one match. The frame test in `frame.rs` gets new bytes. Unit 3 is unmerged, so `conductor/1` needs no bump.
- **`daemon`.** `Log::spawn` takes the `Providers`, and `LogMsg::Welcome` fills the field. `main.rs` builds `Providers` once and clones it to both the log and the registry. `Registry::start` uses `self.providers.of(provider)`.
- **`client`.** `Status` gains `pub providers: Option<Providers>`, which is `None` until the first `Welcome`, as `host` is. `start` publishes `Some(welcome.providers.clone())`. In `new_session.rs`, `StartForm`, `Unavailable`, `StartForm::availability` and the `Availability`-with-`Unknown` enum go away. `Attempt::answered(answer) -> Attempt` replaces `StartForm::answered`, and its test becomes one table of three rejections.
- **`app`.** `NewSession` takes `providers: Option<Providers>`, and `Host` passes `status().and_then(|status| status.providers)`. The segment word comes from `Option<&Availability>`, where `None` means "unknown", before the link is live. A follow-up worth the few tokens: disable the radio of an `Unavailable` provider.

### 2. A running tool that never finishes

I agree with the recommendation and widen it to open requests. In unit 4's `session.rs`, the daemon withdraws a request only when the provider withdraws it (`withdraw`), never on `SessionClosed`. A closed session therefore keeps live Approve and Deny buttons, and `SessionRow` carries an arm that exists only for that case.

The exact change, as measured in `4-end-stops-tools-and-withdraws-requests.patch`:

```rust
pub enum ToolState {
    Running,
    Finished(ToolOutcome),
    /// The turn or the session ended before the call finished.
    Stopped,
}

enum Change {
    Resolve(RequestId, Resolution),
    Finish(ToolCallId, ToolOutcome),
    /// The turn or the session ended: nothing still running will finish, and
    /// nothing still open will be answered.
    End,
}
```

`SessionView::apply` sends `TurnCompleted` and `SessionClosed` through `self.change(Change::End)` before setting the status. `Item::changed` gains two arms before `(item, _) => item`:

- `(Item::Tool { state: ToolState::Running, .. }, Change::End)` gives `ToolState::Stopped`.
- `(Item::Request { state: RequestState::Open, .. }, Change::End)` gives `RequestState::Resolved(Resolution::Withdrawn)`.

`ToolState` is the client's own type, so `Stopped` is not a `proto` outcome, and the host's record stays as the host wrote it. The app adds `ToolState::Stopped => "stopped"`, and the CSS adds `.tool[data-state="stopped"]` to the `declined` rule. A new fold test covers an interrupted turn with a running tool and an open request, and a closed session with an open request. It fails if the `Stopped` arm is reverted.

The cost is +111 tokens of code and +280 of test in `host_view.rs`, plus +8 in `session.rs`. `SessionRow` then drops its `(Closed, _)` arm, because a closed session has no open request, which saves −27 (`5-row-without-the-closed-arm.patch`). This touches the same `Item::changed` that 0040 rewrites. Whichever lands second takes the other's arms.

## Friction

| # | Point | Disposition |
|---|---|---|
| 1 | `directories`, `contains` as a `fold` with `find` | No proposal. One point, and the `fold` with a `match` on `find` is the v6 form. |
| 2 | `label() -> &'static str` rejected | The doc is wrong. See below. |
| 3, 4 | `let` types written as turbofish | No proposal. Bootstrap review §A8 chose turbofish as the one form, and `hedged-dial.md` kept `pat.type` out for the same reason. |
| 5 | `submit`, `bool` lifted into `Option` | Removed in v6 by required fix 5. |
| 6 | `send_on_enter`, compound key test lifted into `Option` | Stays. This is 0028's "filters like a conditional" form. One point is below the bar. See 0040 below. |
| 7 | One status label for row and pane | Removed in v6 by required fix 1. |
| 8 | Fixture shipped because `cfg` lacks features | Removed by required fix 3. No `cfg` proposal (The fixture, (a)). |

**`label()`'s `&'static str`: the doc is wrong, not the tool.** Quality 7's second form in `docs/subset.md` reads `fn label(kind: Kind) -> &'static str`. Three accepted decisions exclude that signature. 0009 allows lifetimes only where a trait impl demands them. Quality 7's first form excludes `&'static str` fields. The p1-u2 review's table-against-match measurement rests on that exclusion. The tool enforces all three. I measured whether allowing `'static` would earn a proposal. `label` goes from 35 to 33 tokens. That is 6%, from two friction points (2 and 7) across three functions, below both bars. The owner should change the example to `fn label(kind: Kind) -> String { String::from(match kind { .. }) }`, which is what the code writes.

## Proposals

**None.** No candidate reaches a 15% score drop or three friction points of one kind. These are the measured candidates:

- **`'static` in a return type** saves 2 tokens per function, from 2 points.
- **`pat.type`** is already decided (§A8).
- **A one-case `if` over library booleans**, for friction 6, saves 15 of 86 tokens (17%). That is 1 point, and 0028 keeps booleans out of `if` by the owner's decision.

**For the owner's decision on 0040** (open on `rv-p1-u3`). 0040's tool change "flags `Some(<expr>).filter(..)` where the `Option` is built at the call". Its guard allows one comparison or one `matches!`, with no `&&` or `!`. `send_on_enter` needs `key() == Enter && !shift() && !is_composing()`, so under 0040 it would have no allowed form left. There are two fixes. 0040 could keep the lift when the predicate combines library booleans. Or its guard could take 0028's full predicate grammar. I recommend the first, because it changes the least.

## Quality: phone and accessibility

Checked against the screenshots and the CSS. The contrast ratios were computed from the CSS variables with the WCAG formula.

**These meet the phone requirements.** The status band pads `env(safe-area-inset-top)`, and the composer, the closed note and the form pad the bottom inset. Both sides pad the left and right insets. `viewport-fit=cover` is set. Every button has `min-height: 44px` by default, and the 36 px "New session" pill and the 34 px Interrupt pill grow their hit areas to 44 px with `::after`. Inputs use 16 px text, so iOS does not zoom. `touch-action: manipulation` is set, and hover styles sit under `(hover: hover)`. The phone layout shows one screen at a time with a back button, as §3.2 asks. A session the host forgets falls back to the list, so the phone always has a way out.

**Keyboard: not verified.** `interactive-widget=resizes-content` with `100dvh` keeps the composer above the keyboard in Chromium. iOS Safari ignores `interactive-widget`, and `dvh` does not shrink for the keyboard there. On iOS, the page likely pans and the pane header scrolls away. That is a guess, because no screenshot shows the keyboard open and Playwright cannot emulate it. Add this check to unit 8's smoke test on the iPhone. If it fails, the fix is a `visualViewport` resize listener that sets the shell's height.

**Required fixes for accessibility** (CSS and attributes only, no token cost to speak of):

1. **Text below 4.5:1.**
   - `.by` and `.turn-end` use `--faint`, at 2.68:1 on white in light mode and 3.48:1 in dark mode.
   - Placeholders use `--faint` at 2.4:1 on `--canvas`. The composer's placeholder carries the session's state ("Claude Code is working…").
   - Light "Available" is 4.2:1 on the unselected segment.
   - Dark "Unavailable" is 3.65:1 on the selected segment (`#46464c`).

   Use `--muted` for the first three, which gives 5.27:1 on white and 4.72:1 on the canvas. Darken the light `--green`, and lighten the dark `--segment` or raise the dark `--red`, until each pair reaches 4.5:1.
2. **`.notice` is `button` with `role="alert"`**. The role replaces the button role, so assistive technology no longer announces it as something to press. Put `role="alert"` on a wrapping element, and raise `min-height` from 40 px to 44 px.
3. **A tool's outcome is invisible to assistive technology.** `.tool-mark` is `aria-hidden`, and the outcome exists only as `title` and `data-state`. Give the mark `role="img"` and `aria-label` set to the state word.
4. **The transcript is silent.** Add `role="log"` to `.items`, so that new replies, tool calls and requests are announced politely.

Two more items are recommended, not required. When a phone opens a session, the focus stays on the row, which `display: none` has just hidden. Move the focus to the pane's heading. The send button is enabled with an empty draft and then does nothing (`phone-light-idle.png`). It could be disabled until the draft has text.

Dark mode reads well otherwise. The ratios are approve 7.46:1, interrupt 5.88:1, row amber 9.66:1, and accent on soft 6.02:1.
