# Review: subset version 7, the guard and the effects `for`

This is the reviewer's pass over `subset-v7` at `6b1087d`, against `main` at `3b7b30c`. The contract is proposals 0040 and 0041 with their owner decisions, and `docs/p1/design.md` §12. The owner's rule for 0041 is that a loop whose body necessarily performs side effects may be a `for`, and every other loop stays comprehension style. The round has no friction log.

Every adversarial input below was checked with `subset check` under the branch's `subset.toml`, one file at a time, placed at `crates/daemon/src/a.rs`. The inputs need not compile, since the checker reads syntax only, unless the text says they were built.

The verdict is **accept after the required fixes**. The rewrite in `crates/` is correct and the measurements reproduce. The checker has four holes that let the replaced forms or an `if` back in (required fixes 1 to 4), one site breaks 0040's rule text (fix 5), and the docs contradict each other on the `matches!` guard (fix 6). Two second forms remain that only the owner can settle (One way, below).

## Compliance

`subset check` reports nothing on the branch. `SUBSET=1 tools/check.sh` passes on `6b1087d`: fmt, clippy native and wasm, 767 tests with 0 failed, and `subset check`.

The rewrite keeps the seven qualities. `session.rs` is the clearest gain. Each step's state change and its emit now sit in one arm, where before a reader matched a `settle` arm to an `effect` arm through `Effect`. The guards in `host_view.rs`, `serve.rs`, `codex_replay.rs` and `e2e.rs`'s `Hop` each compare a value the arm's pattern bound, and each has a written-out fallback.

## Measurements

`docs/subset/measurements/v7/measure.sh` reproduces the numbers. Over the eight files, tokens go from 29,536 to 29,258, which is -278 or **-0.9%**. The score goes from 28,145.5 to 27,938.0 under version 6's tool, -207.5 or -0.7%. `session.rs` goes from 2,349.5 to 2,211.5, **-138.0**, the same delta 0041 measured at `1d1cabe` (2,400.0 to 2,262.0). `e2e.rs` falls 29 tokens even with its six `.unwrap()` calls, because the `append` helper loses its `collect` and its assertion.

The fallback check is right on every case I tried. It accepts a real fallback: `_`, a binding, an or-pattern covering an or-pattern (`Some(A(_) \| B(_))` after `Some(A(s) \| B(s)) if ..`), a top-level or-pattern on the guarded arm, a literal (`(1, _)` after `(1, s) if ..`), `ref` and `x @ ..` bindings. It rejects a missing one, and a fallback split into `Some(A(_))` and `Some(B(_))` as documented. Since Rust's exhaustiveness check ignores guards, a missing fallback can't compile anyway, so the check only ever decides whether the fallback is one arm. `all_cover` refuses any tuple or tuple-struct pattern containing `..`, even two written alike, but `pat.rest` is outside the subset in those positions, so no subset code reaches it.

## Required fixes

1. **A guard compares a value its pattern bound.** 0040's rule says the guard is for "when the arm depends on a value its pattern bound". The checker never looks, so `match x { _ if a == b => .., _ => .. }` is an `if`/`else` that passes. Flag a guard unless one operand names a binding from the arm's pattern. That check does not catch `Some(v) if v.is_empty() == w.is_empty()`, an equality of two library booleans, because `v` is bound. The checker can't see that a method returns `bool`, so list that case under review checks in `compromises.md`. Failing input:

   ```rust
   fn pick(x: Item, a: Seq, b: Seq) -> Label {
       match x {
           _ if a == b => Label::Same,
           _ => Label::Other,
       }
   }
   ```

2. **`matches!` in a guard is checked.** The checker does not parse the macro's tokens, so `matches!(a && b, true)` carries any boolean and a `true` literal through, and `matches!(x, P if a || b)` carries an inner guard. Parse the macro's arguments as an expression and a pattern, and reject an inner `if` and a scrutinee that is not a place or a call. The hole is older than v7 (`filter(|x| matches!(x.seq == b && x.live(), true))` passes too), but 0040 opens a second place for it. Failing input:

   ```rust
   match v {
       Some(v) if matches!(v.is_empty() && w.is_empty(), true) => Label::Same,
       Some(_) => Label::Other,
       None => Label::None,
   }
   ```

3. **Flag the lift by what it does, not its spelling.** Flag `eq`, `ne`, `lt`, `le`, `gt`, `ge` and `is_eq` called by name anywhere outside a predicate closure, as 0040's tool section already says, and flag `PartialEq::eq` as a path call. Flag `.filter` with one comparison when the receiver is a binding of a `Some(..)` built in the same block, a full `Option::Some` path, or `Some(..).into_iter()`. Treat `!(one comparison)` as one comparison. Failing input: `a.lt(&b).then_some(x)`.

4. **The `for` body and its loop are value-free, and effects have one form.** Reject a block with statements, an assignment or a `let` anywhere in the awaited call's receiver and arguments, and in the `for`'s iterator expression. Reject an `.await?` inside the receiver of another awaited call. Flag `try_for_each` and `try_collect` on any chain that starts at `stream::iter`, whatever the position, unless the collected type is a list of something other than `()`. Failing input, in a `SessionActor` method:

   ```rust
   for kind in kinds {
       self.emit({
           self.turn = Turn::Idle;
           kind
       })
       .await?;
   }
   ```

   and `n0_future::stream::iter(kinds).map(Ok).try_for_each(|kind| self.emit(kind)).await`.

5. **`s2.rs:562` breaks 0040's rule.** `(Some(_), Some(TurnOutcome::Completed)) if resumed.id == a.id` compares two values that no pattern bound. Fix 1 will flag it. Put the id in the scrutinee: `match (&resumed.id, s.turn.text.find("a.txt"), &s.turn.outcome) { (id, Some(_), Some(TurnOutcome::Completed)) if id == &a.id => Verdict::Pass, _ => Verdict::Fail }`.

6. **The `matches!` guard and the literal guard contradict §A3 and §A4.** The bootstrap review now says "The nested match stays the form for a guard against a literal or a variant", and §A4 says to compare with a literal by matching on it. The checker, the tool test `a_match_guard_is_one_comparison_with_an_unguarded_arm_after` and `docs/subset.md` all accept `Some(Item::Request { kind, .. }) if matches!(kind, Kind::Write)`, which is `Some(Item::Request { kind: Kind::Write, .. })`, and `Some(seq) if seq == Seq(0)`, which is `Some(Seq(0))`. Flag a `matches!` guard whose first argument is a path rooted in a pattern binding, and a comparison guard with a literal, a unit variant or a constructor of literals as an operand. A `matches!` on a call result, `matches!(item.kind(), Kind::Write)`, keeps the guard, since a pattern can't call a method. Change the tool test to use that.

## Where the rules were bent

**`e2e.rs`'s `append`.** The subset bans no method by name, and `e2e.rs` already calls `.unwrap()` 41 other times, so the six new calls are allowed. They are also the best form here. The `for` body can't hold `.await.unwrap()`, since its statements end in `?`, so the helper has to return `Result`. Each `unwrap` then panics with the `Stopped` value at the failing line, which the old `assert_eq!(.., 0)` on a count did not report. Making each test return `Result` instead would change six test signatures to save six calls.

**`s1.rs`'s `cmp` against `Ordering::Equal`.** This is a sign the guard is narrow, but the answer is already in the rule. `cmp` exists to order (0024, §A4). Here it tests equality only because `Vec<String>` and `String` happen to be `Ord`, so the same check on a `PartialEq`-only type has no `cmp` and would need yet another form. One guard that compares two tuples is one comparison, needs only `PartialEq`, and passes `subset check`:

```rust
match (presence(&a), t.result()) {
    (Presence::Present, Some(("success", Outcome::Succeeded)))
        if (&t.permissions, &t.streamed)
            == (&Vec::from([String::from("Write")]), &t.text) =>
    {
        Verdict::Pass
    }
    _ => Verdict::Fail,
},
```

On a scratch copy of `s1.rs` that goes from 2,784.5 to 2,770.0 score and from 2,937 to 2,917 tokens, and the `std::cmp::Ordering` import goes. `cargo clippy -p agents --bin s1 -D warnings` passes on it. I recommend it, and changing the note under `examples.md` §25 to say "compare a tuple of each side in one guard" instead of pointing at `cmp`. That makes the guard the one form for any number of equalities. It doesn't cover several orderings at once, which stay `cmp` in the scrutinee's tuple.

**The split fallback.** It hasn't bitten yet. Of the nine guards in `crates/`, none needed its fallback split. `host_view.rs` added `Change::Finish(_, _)` and `Change::Ask(_, _)` to an existing catch-all arm, which Rust's exhaustiveness check demands anyway. It bites when the otherwise case differs by variant, as in `Some(x) if x == y => A, Some(Shape::A(_)) => B, Some(Shape::B(_)) => C`. The rewrite is one unguarded arm with a nested `match`, a few tokens. I expect it rarely and don't propose a change.

## One way

**Comparing two runtime values to choose an arm.** After the fixes, the guard is the form, with these second forms left:

- **`cmp` matched against `Ordering::Equal`.** `s1.rs:351` and `:354`, and `examples.md` §25's note recommends it. Every `Ord` equality can be written this way and pass. The tuple guard above removes the reason for it. To make it one way, flag a `match` whose arms for a `cmp` scrutinee are `Ordering::Equal` and a catch-all.
- **A filter on an `Option` that already exists, matched at once.** `link.rs:710` (`match self.cursor.filter(|cursor| cursor.epoch == welcome.epoch)`), `s2.rs:225` (`match event_turn(&event).filter(|got| got != &&turn.id)`), and `client/examples/headless.rs:301` (`let due = self.reconnect_after.filter(..)`, then an `if let`). 0040 keeps `filter` on an existing `Option`, but `docs/subset.md` calls the guard the one form for choosing an arm this way. The guard rewrite of `link.rs:710` (`Some(Cursor { epoch, .. }) if epoch == welcome.epoch => Ok(()), Some(_) | None => ..`) scores 5,441.5 against 5,441.0 and passes the check, so it is a tie on size. The owner should decide whether a `filter` whose result is a `match` or `if let` scrutinee counts as a lift. `stun.rs:135`, a `filter` ending in `?`, selects, and stays either way.
- **A lift with `&&` over comparisons.** `Some(x).filter(|x| x.seq == b && x.name == d)` passes, since the amendment keeps lifts that combine booleans. The amendment speaks of "library booleans", and its example is the Enter-key check, whose parts are method results. If comparisons joined by `&&` count too, two equalities have two forms, this and the tuple guard. Saying that the amendment covers only predicates with at least one library `bool` call would leave one.

**Running effects in sequence.** After fix 4, `for` is the form for awaited effects. One second form is left on purpose by the owner's wording: synchronous effects run through `for_each`, as in `agents/src/claude/session.rs:505` and `agents/src/codex/server.rs:523` (`self.pending.drain().for_each(|(_, Pending { reply, .. })| { .. })`). The owner's rule ("a loop whose body necessarily performs side effects may be a `for`") covers them, but the accepted text and the checker allow only awaited calls with `?`. Either the `for` takes synchronous effect calls too and `for_each` with a block body becomes the violation, or the docs say that synchronous effects are `for_each`. `join_all` at `link.rs:700` runs effects concurrently, a different thing, and stays.
