## The session actor

- **Held interrupts (§11).** `Turn = Idle | Starting(Held) | Running(NativeTurn)` is the design's state machine. `Send` from `Idle` moves to `Starting(Nothing)` only when `send_user` succeeds. `Interrupt` while `Starting` stores `Held::Interrupt` and answers `Accepted`. `TurnStarted` moves to `Running` and sends a held interrupt then. `TurnEnded` returns to `Idle`, which drops a held interrupt that never went out. `TurnStarted` while `Idle` also moves to `Running`. That is right, because a turn the CLI starts on its own is still a running turn. The gated e2e test passes only if the interrupt waits for `init`, and all five live runs (three at the tip, two after fix 1) took the held path.
- **First decision wins.** `resolve` reads `requests` and stores `Resolved` before it awaits anything. Commands are handled one at a time on the actor's task, so a second `Resolve` always sees the first. The e2e test sends both from the same client, though, so it can't tell "rejected with the first resolver's name" from "rejected with my own name" (fix 5).
- **Settle, then perform.** `apply` settles every step, then performs the effects in order. No effect is lost or reordered: the effects come out in step order, and no other input runs until `perform` returns. The only effect that can fail partway is a log append. That fails only when the log actor is gone, and then the session ends with the host anyway. A failed interrupt is logged as an `Error` and the loop goes on. The split moves state ahead of the log within one batch, but nothing can observe that, since the actor handles no other input until the batch is done.
- **`Exited` to `SessionClosed`.** `ClaudeEvent::Exited` maps to `Step::Closed`, which logs `SessionClosed { Exited }` and ends the actor. A later command gets `Stopped`, and `serve.rs` answers `Rejected(SessionClosed)`. No test covers this path, at either level (fix 2 and fix 4).
- **Withdrawn requests.** `withdraw` finds an open request by its native id and marks it `Withdrawn`. A cancel for a request already decided finds nothing and logs nothing, which is right. Only the mapping test covers it. No e2e test plays the recorded cancel (`session1-approve-deny-interrupt.jsonl` turn 8, `replay.rs` "3b") (fix 3).
- **The turn ending with requests open.** The session doesn't withdraw them. In the recording, the CLI cancels before it ends an interrupted turn, so the log is consistent there. When the process exits with a request open, the request stays `Open` in the log for good. The fold should treat a closed session's open requests as moot (unit 6, below). The host needs nothing more: `SessionClosed` already says it, just as `TurnCompleted` already says the turn is over.
- **Commands and agent events.** `select!` takes `inbox.recv()` or the feed's `recv()`. Both are cancel-safe, so a lost race drops nothing. While the actor awaits `send_user`, `respond` or `interrupt`, the agent's events wait in the feed (capacity 1,024).
- **Two small risks, not fixes.** A `Resolve` that races the CLI's cancel logs `RequestResolved { Decided }`, then an `Error` from `respond` ("unknown permission request"). The first decision still wins, and only the `Error` is noise. Also, nothing times out `initialize` or a control call. A CLI that hangs without exiting hangs its session's actor, though not the registry or other sessions.

## F1: no `for … .await`

The split is the only v6 form for this code. `stream::iter(steps).then(|step| self.step(step))` can't hold `&mut self` in an `FnMut` across an await. I also estimated a v6 redesign that batches the appends (`Log::append_all`, with mapping returning one `Step` of `Entry`s). It saves about 150 tokens in `session.rs`, and a second enum in `mapping.rs`, its tests and the log actor cost back about 115. That is a net of roughly -35 tokens, so it is not required. This is an estimate. I did not write it out.

**Proposal 0041** (`docs/subset/proposals/0041-expr.for.await_each.md`) allows `for item in list { self.method(item).await?; }` as a statement in a `&mut self` method of loop state, tolerated. On the affected code (`Effect`, `apply`, `perform`, `settle`, `withdraw`, `effect`), the score goes from 616.5 to 478.5 (-22.4%) and the tokens from 692 to 516. All seven qualities hold. The one judgment for the owner is quality 6. The rule draws its line by receiver: `for` inside loop state, `then` everywhere else. The general rule would also take `e2e.rs`'s `append`. It measures -10.2% with that site and fails the threshold, which is why the rule is narrow. 0041 is the next free number: `main` and `rv-p1-u3` stop at 0040, and no local branch has a 0041.

## F2: `let x = tokio::select! { .. }`

This is a checker gap, confirmed. 0007's text allows a loop turn whose input is a `select!`, and `takes_input` accepts a bare `select!` statement. In a `let`, though, it only asks `awaits(&init.expr)`. `awaits` walks the syntax tree, and a macro's tokens are never parsed, so a `let` bound to `select!` is rejected. I reproduced it with `session.rs` rewritten that way: `session.rs:227:9: expr.loop: a loop turn takes one input ...`.

The fix, in `f2-checker.diff`, changes `tools/subset/src/actor.rs` `takes_input`:

```rust
Stmt::Local(local) => local.init.as_ref().is_some_and(|init| {
    init.diverge.is_none() && (awaits(&init.expr) || is_select_expr(&init.expr))
}),
```

The new test `a_loop_turn_may_bind_its_input_to_a_select` passes `let input = tokio::select! { .. }; self.on(input).await?;`. It still rejects a `select!` nested in a call (`let input = Input::from(tokio::select! { .. });`). With the fix, the rewritten `session.rs` checks clean and `cli.rs` passes (89 tests). `agents/src/claude/session.rs` matches on its process state, and its `next_input` stays as it is.

## Unit 6 (`p1-u6-screens`)

- **Every event unit 4 emits is folded.** `SessionView::apply` has one arm per `EventKind`. The live run's order folds into `User`, then `Tool` (Running to `Finished(Succeeded)`), the `Request` resolved by `live`, `Reply` (Streaming to Done) and `TurnCompleted`. On an interrupt, the cut-off text arrives as `AssistantMessage` and replaces the deltas. Unit 4 never emits `Error` on the happy path.
- **Requirement for unit 6: a closed session's open requests.** `SessionView::attention` counts `RequestState::Open` whatever the status. A session whose CLI exits with a request open therefore shows as waiting on a person for good, and `Resolve` on it gets `Rejected(SessionClosed)`. On `SessionClosed`, the fold should mark its open requests `Resolved(Withdrawn)`, or `attention` should answer `Quiet` for a closed session.
- **Tool calls left `Running`.** The recordings show the CLI sends a `tool_result` for every tool call it interrupts (turn 8, now fix 3's test). A call stays `Running` only if the process dies mid-tool. On `SessionClosed`, the fold should finish any `Running` tool as `Failed`, for the same reason as the requests. No `Bash` interrupted mid-run has been recorded. If one ever shows the CLI skipping the result, `TurnCompleted` needs the same treatment.
- **For the owner, before unit 5 freezes the wire.** The session now knows which tool call a Claude request asks about (`Step::Open { call }`), but `RequestOpened` doesn't carry it. So the screen can't place a request on its tool card. The unit 3 review's open item 1 (`RequestOpened { request, tool: ToolKind }`) is still undecided. Adding `call: Option<ToolCallId>`, or deciding that item, costs one ALPN bump now and more later.
