# Review: unit 3, the protocol swap, in subset v6

This is the reviewer's pass over `130b3c4` (`git diff 087c1c2 rv-p1-u3`) and the implementer's 9 friction points in `.audit/p1-u3.friction.md`. The implementer wrote the unit under subset v5. `main` is now at v6, so the review checks a scratch merge of `main` into the branch with the v6 tool. The contract is `docs/p1/design.md` §1, §2.1 to §2.4, §2.8, §2.9, §3.1, §4.2, unit 3's row in §5, the volume budget in §6, and the owner decisions in §8 to §11 as they stand on `main`.

`docs/subset/measurements/p1-u3/measure.sh` reprints every score and token count below. Run it from the root of that merge. `required-fixes.diff` in the same directory holds fixes 1 to 4. With the diff applied to the merge, `tools/check.sh` passes (749 tests) and `subset check` reports nothing.

## Verdict

**Approve after the required fixes.** The protocol matches §1 type for type, minus the serde attributes that postcard made pointless. The daemon's actors match §2.3, §2.4 and §2.8. The fold matches §3.1. Unit 3's "done when" holds:

- the wrong-token and epoch e2e tests pass;
- `StartSession` answers `ProviderUnavailable`;
- `log.rs` tests replay after the cursor;
- the app builds for web (`cargo build -p app --features web --target wasm32-unknown-unknown`) and for desktop (`--features desktop`).

On the merge with `main`, `subset check` (v6) reports nothing. The postcard swap is sound.

Five fixes are required: four volume fixes and one doc fix. Together they take the touched files from 9,092 to 8,699 tokens (-4.3%) and from a score of 8,846.5 to 8,479.5 (-4.1%). One proposal follows (0040). A real `conductord host` reached Live with the headless client from a ticket whose only address is n0's relay.

The draft of this review had a sixth fix. It called `request.eq(id).then_some(..)` in `host_view.rs` a breach of quality 6 and asked for `Some(resolution).filter(|_| &request == id)`. That fix is withdrawn. Bootstrap review §A4 names `.eq(..).then_some(..)` as the form for equality of two runtime values, and the replacement fails `clippy::some_filter` on the pinned nightly. The two spellings of one equality in this diff are friction (U1), and 0040 proposes the shorter form.

### Required fixes

Fixes 1 to 4 are in `required-fixes.diff`, formatted with `cargo fmt`. The savings are measured under v6.

1. **`AuthToken` derives serde, and its hex impls go.** `proto/src/ticket.rs:71-81` serialises the token as 32 hex digits through a hand-written `Serialize` and `Deserialize`. Those impls existed so the JSON frame was readable. Postcard isn't readable, so the token now crosses the wire as a 33-byte string where 16 raw bytes would do. The fix:
   - derives `Serialize, Deserialize` on `AuthToken([u8; 16])`;
   - deletes the two trait impls, `to_text`, `parse`, `TicketError::Token`, the `HEXLOWER` import and the hex round-trip test (the `Debug` assertion stays);
   - changes the `Hello` frame test to 16 literal `\xab` bytes, and it passes.

   **Saving:** -265 tokens and -262.5 score, plus two fewer tolerated trait impls. Every `Hello` gets 17 bytes smaller.
2. **The feed's dedupe is unreachable, so delete it.** `LogActor::on` builds the replay and calls `live.subscribe()` in one actor turn. Appends are handled in the same actor, so none can land between the two. A `broadcast::Receiver` from `subscribe` gets only values sent after the call. So no live event can carry a seq the replay already holds, and `Feed::write`'s `match event.seq.cmp(&self.last)` never takes its skip arm. The fix:
   - deletes `Feed::last`, `Feed::write`, and the `Ordering` and `HostSeq` imports;
   - writes `Upcoming::Event(event) => self.send.write(&event).await?`;
   - says on `Feed` why the replay and the feed neither overlap nor leave a gap.

   The reconnect e2e still asserts contiguous seqs with no duplicates, and it passes. §2.3's sentence "then skip live events at or below the last replayed seq" should go from the design with this fix. **Saving:** -95 tokens, -87.0 score.
3. **The boundary table sends with `join_all`.** `e2e.rs:232-241` unzips the cases with a four-type turbofish (U4), then sends them in order through `stream::iter(..).then(..)` (U3). The four commands are independent. `n0_future::join_all(cases.iter().map(|case| link.send(case.body.clone())))` sends them and keeps their order in the result, and the assertion maps `cases` to their `result`. **Saving:** -14 tokens, -6.5 score. It removes U4 and one of U3's two sites.
4. **`Serving` goes, and `announce` takes what it prints.** `daemon/src/main.rs:60-65` defines a struct only to carry four values from `host` to `announce`. After the fix, `host` builds the ticket, spawns the router, calls `announce(&data_dir, &web_url, &ticket)` and returns the `Router`. The router still accepts before the ticket is printed. **Saving:** -19 tokens, -11.0 score.
5. **The ALPN rule says what "breaking" means under postcard.** `proto/src/lib.rs:12-13` says "any breaking change to these types bumps ALPN", and `ALPN`'s doc says the types "change incompatibly". Under postcard almost every change breaks:
   - a variant is its index and a field is its position, so reordering variants or fields decodes as the wrong value with no error;
   - appending a variant makes an old peer fail mid-stream, which is the failure the bump exists to prevent.

   The case is real, because a Home Screen web app keeps running its cached build against a newer host. Write the rule out. Any change to a type reachable from `Open`, `HelloReply`, `CommandResult`, `Event` or `Signal` bumps `ALPN`, including a variant added at the end. Renaming a variant or a field doesn't change the bytes. **Saving:** none, because comments score nothing.

### Advisory, not required

- **Check the epoch inside the log.** `Conductor::feed` asks the log for `Welcome` only to read its epoch, then asks again to subscribe. That is correct, because the epoch never changes within one log. `Log::subscribe(Subscribe) -> Result<Option<Subscription>, Stopped>` would check the epoch and attach in one round trip. This is a clarity change, not a volume one.
- **Untested decisions.** `SessionView::controls` and the feed's other-epoch branch have no test. Unit 6 should test `controls` and `attention` against literal values when it adds `attention`.
- **Labels in markup.** In `app`, `TranscriptItem` maps `ToolOutcome`, `ToolKind`, `TurnOutcome` and `Decision` to text, and `SessionPane` maps `Provider` to text. 0018 puts decisions in `client`. Unit 6 can move these into `host_view` as `label` matches. §3.1's `PROVIDERS: &[ProviderChoice]` with `label: &'static str` no longer fits quality 7 as `main` now words it (a string-keyed `const` is a `match`), so the design should change it to `Provider::label`.
- **`docs/architecture.md` D8 on `main`** now says postcard but keeps JSON's rationale ("easy to debug, tolerant of schema changes"). It also lists "postcard or bincode" as the alternative not taken. That row needs rewriting.
- **Durability inherits the bump.** §10 stores postcard values in `redb`. A stored event can't be read after a `proto` change, so an ALPN bump will also need a store version, and either a migration or a fresh log. That belongs in the durability slice's design.
- **`tools/s3-native.sh` and `tools/s3-browser.sh`** now call `conductord host`. They can't pass until unit 7, because `headless` requires `--directory` and no host can run a turn yet. They also conflict with `main`'s `tools/target-dir` change. The merge takes `main`'s `"$target"` paths with `host`.

## The protocol, against units 4 to 7

The `proto` types are §1 verbatim, minus the serde attributes. I read them against unit 2's event shapes as merged on `main` (`crates/agents/src/{claude,codex}/protocol.rs` and `claude/PROTOCOL.md`) and against §11. They carry what units 4 to 7 need.

- §11's held interrupt needs nothing new from the wire. The client offers Interrupt while its folded status is `Running`, and `UserMessage` sets that status. The host's `Starting(Interrupt)` answers `Accepted`, so the client's view and the host's state never disagree on whether to offer it.

No gap requires a change in this unit. Three items need a decision or a line in the design before unit 4:

1. **`RequestOpened` repeats `ToolCall`'s job in a weaker shape (the owner's call, before unit 4).** `ToolCall` carries a typed `ToolKind`, and `RequestOpened` carries `tool: String, detail: String`. Both describe the same tool action, and often the same call: Claude prints the `tool_use` block and then `can_use_tool` for it (`fixtures/e2e/claude-approve.jsonl`). With `RequestOpened { request, tool: ToolKind }`, one mapping function and one renderer would serve both:
   - Claude's `(tool_name, ToolDetail)` goes through the same `tool_kind` as `ToolUse`;
   - Codex's `Command { command }` becomes `ToolKind::Command`;
   - Codex's `FileChange { reason }` and `Permissions { reason }` become `Other` with that reason.

   This changes §1.4 as approved, which is why it's a question and not a fix. Deciding it now costs nothing. After unit 4 it costs an ALPN bump.
2. **A denied Claude tool shows as `Failed`, not `Declined` (unit 4).** A deny comes back as a `tool_result` with `is_error: true` (`PROTOCOL.md`, step 2), so the §2.7 mapping gives `Finished(Failed)`. Telling the two apart needs the `tool_use_id` that `can_use_tool` carries (`PROTOCOL.md`), and `main`'s `ClaudeEvent::PermissionRequested { id, tool_name, detail }` doesn't expose it. Either unit 4 adds it at the agents boundary, or the design says `Declined` is Codex-only.
3. **A failed send must end the turn (unit 4).** §2.5's `Send` row logs `UserMessage`, then calls `send_user` or `send_turn`, and the fold sets `Running` on `UserMessage`. If the call fails, the session must log `TurnCompleted { Failed }`. Otherwise every client shows the session running forever.

These were checked and are fine:

- **Deltas then the final message are adjacent in both providers.** Claude prints the `assistant` block before `content_block_stop`. Codex's `item/completed` follows the item's deltas. So the reply rule never shows text twice.
- **An interrupt mid-stream** prints the cut-off text as the final message, which replaces the deltas.
- **Codex's `Failed { message: Option<String> }`** maps to an empty string.

## Postcard

- **Stable.** The frame body is `postcard::to_allocvec` and `from_bytes`, using postcard 1.1.3 with `use-std`. Postcard's wire format is fixed for 1.x. Every `proto` type is a struct, a newtype or an externally tagged enum, all of which postcard encodes. Nothing uses `deserialize_any`, `flatten`, `untagged` or `skip_serializing_if`.
- **Deterministic.** No `HashMap` or other unordered collection crosses the wire, so one value has one encoding. That will matter when `redb` stores the same bytes.
- **The literal-bytes tests are honest.** I decoded each expectation by hand against the declaration order:
  - `SendMessage` is `Open` 2, `CommandBody` 1, session 2, `"hi"`;
  - `RequestResolved` is `EventKind` 8, then `Decided` 0, `Approve` 0, `"phone"`;
  - `TurnCompleted` is 9 with `Failed` 2;
  - `ProviderUnavailable` is `Rejected` 2, variant 1;
  - `Signal::Selected` is 2 with `Srflx` 1 and `Prflx` 2.

  The bytes are literals, not computed, so reordering any enum they cover fails them. They pin 19 of the 59 variant indices in `proto`. The ALPN rule (fix 5) has to cover the rest.
- **wasm builds.** `check.sh` runs clippy for `proto`, `client` and `app --features web` on `wasm32-unknown-unknown`. A real `cargo build -p app --features web --target wasm32-unknown-unknown` also succeeds.
- **The bump policy is written down** in `proto/src/lib.rs`, in `ALPN`'s doc and in design §10, but not precisely enough (fix 5).
- **Size.** The implementer's commit reports an assistant delta shrinking from 82 to 19 bytes. I didn't measure that. Fix 1 takes 17 bytes off every `Hello`.

## Gap-free replay and the log actor

- **Order.** `LogMsg::Subscribe` snapshots the events after the cursor and subscribes to the broadcast in one call of `LogActor::on`, so the live receiver starts exactly where the replay ends. `Feed::next` drains the replay before it reads live. Nothing falls between and nothing repeats, which is why fix 2 can delete the dedupe.
- **The client goes Live before the host has subscribed it.** In the live run, the host logged `command` (the client's `StartSession`, sent on Live) 0.8 ms before `subscribed`. That is harmless. The subscription starts from the client's cursor, so an event appended in between is still replayed.
- **Epoch.** A `Subscribe` from another epoch closes the stream. The client already resets on the `Welcome` it gets at `Hello` (`a_cursor_from_another_epoch_starts_over_from_the_beginning`), so this branch only guards a client that ignored its `Welcome`.
- **A slow subscriber.** `Log::append` never waits on a subscriber, because `broadcast::send` drops the oldest value for a lagging receiver. Each feed has a buffer of `LIVE_BUFFER` (1,024) events. A feed that falls further behind gets `Lagged`, finishes the stream, and the client resubscribes from its cursor. A slow QUIC or data-channel write blocks only that feed's task. This converges as long as the client takes in a replay plus 1,024 events faster than the host appends them. The log itself grows without bound, as §8's decision 3 accepts for slice 1.

## Friction points

- **U1, equality outside a predicate, four sites.** `host_view.rs` uses §A4's `.eq(..).then_some(..)`, and `serve.rs` uses 0028's `Some(x).filter(..)`. Both are allowed in v6. **Proposal 0040** measures a guard on all four sites.
- **U2, a loop that ends with nothing to return, three sites.** Not proposed. Two sites are of the same kind (`serve.rs` `channels` and `app` `follow`), and `events_through` needs `break events` either way. Allowing a bare `break` takes `follow` and `run_link` from a score of 288.5 to 268.0 (-7.1%) and from 302 to 280 tokens, under 15%. It is worth watching. `follow` returns `Err(SendError::Stopped)` for a link that ended normally, an error value invented to satisfy the loop rule, which bends quality 4.
- **U3, sequential awaits over a list, two sites.** Fix 3 removes one. The other (`append`, in a test) remains, one site. Not proposed.
- **U4, `_` in a turbofish.** Removed by fix 3.
- **U5, no `*` on a `Copy` value.** `Iterator::copied()` is the v6 form: `.filter_map(..).copied().collect::<Vec<Epoch>>()`. Not proposed. One site.
- **U6, fixed-size random values.** Already ruled. `bootstrap-review.md` §A11 rewrote `random<const N: usize>()` as `getrandom::fill` on a local array, and one fn per size follows that ruling. Not proposed again.
- **U7, a one-platform constant.** Accepted. 0016 exempts a module that exists on one platform, and the `storage` module reads well.
- **U8, clap flags in a subcommand.** Accepted. `HostArgs` with `ArgAction::SetFalse` keeps `!` out of `main`.
- **U9, popping the last item.** Accepted. Changing the last item needs it owned, which `pop` gives. `last_mut` needs `&mut` on a value that isn't loop state (0008). A slice pattern (`pat.slice`) would only replace the inspection, not the `pop`. No construct shortens it without weakening forward data flow.

## Tool notes

- **Two forms for one equality.** The checker accepts both `a.eq(b).then_some(x)` (§A4) and `Some(x).filter(|x| x.a == b)` (0028), and this diff uses both. If 0040 is rejected, the owner should still pick one of the two, and the checker should flag the other.
- **Scoring a proposed rule.** `subset score` can't price a construct whose rule the checker doesn't know yet, so 0040's after score is corrected by hand (24.0 off). A `--allow <id>=<tier>` flag that also lifts the matching placement rule would make such proposals reproducible without arithmetic.
