## The contract

**Gating.** Both gates do what units 4 to 7 need. `await` matches from a cursor that sits just past the previous match, not from the time the fake reaches the marker. So a user message that the session writes before the fake reaches the marker still opens the gate, and the test has no race on that side. Output order is file order, and a slow machine can't reorder it. The only time-dependent rule is the 5 s `serverRequest/resolved` timeout carried from today's Codex fake (see the advisory list).

**The silence check.** I checked it by breaking each gate on purpose.

| Mutation (reverted) | Result |
|---|---|
| `await` made a no-op in `fake-cli.py` | fails at `replay.rs:462` (the first `early`), 5 runs of 5, in 0.08 to 0.20 s |
| Same, under 16 busy loops on 8 cores | fails 5 runs of 5, in 0.17 to 0.45 s |
| `control_response` marker removed from the fixture | fails at `replay.rs:480` (the second `early`), 3 runs of 3 |
| `await` match that never occurs | fails at `replay.rs:442` (`"an event arrives"`) after the 20 s timeout |

A 300 ms window can only miss a regression. It can never fail a correct gate, because a correct gate produces no output in that window. So the check gives no flaky red results, only possible false greens. A false green is unlikely, because `ClaudeSession::spawn` awaits the `initialize` response (`claude/session.rs:160`). That means the fake is already running and has its next line ready when the window opens, and a leaked line arrives within milliseconds even on an oversubscribed machine. I looked for a better observable and found none that is deterministic and also cheaper. Proving that something did not happen needs either a time bound or a report from the fake ("waiting at marker N"), and a report from the fake is a proxy for the behaviour this test should observe. The timing window stays.

**Deferral of three recordings.** This is sound, but it is not written down anywhere. Owner decision 2 (§8) makes Claude replies stream, so both `claude-*` recordings have to come from the new `s1` recording that unit 2 makes. Building `claude-deny-interrupt.jsonl` from `session1-…` now would mean building it twice. The same applies to `claude-approve.jsonl`. As committed, it has no deltas, but §4.1 line 966 says it plays "message, deltas". So it is provisional until unit 2 too. The Codex recordings have no such dependency, but unit 5 is their first consumer. The marker semantics are already tested through the Claude path, and the implicit Codex rule is tested through `codex_replay`.

### Advisory, not required

- **The 5 s resolved timeout is a timing gate.** `fake-cli.py:71` plays a `serverRequest/resolved` after 5 s even when no answer has arrived, because Codex also resolves requests it withdrew. In unit 7 the approval comes from a browser click. If a slow WebKit run takes longer than 5 s to click, the fake resolves before the answer and the host sees a different event order. This is carried over from `main` and was out of scope here. Unit 5 or unit 7 should replace it for e2e recordings with an explicit `await` before each withdrawn request's `resolved`, so that no gate depends on time.
- **`match` compares top-level keys only.** That is enough for `claude-approve`, and with the cursor it is enough for an ordered recording. Codex's two-thread recording would gate `turn/start` on `{"method": "turn/start"}`, which can't tell the threads apart, because `threadId` is nested in `params`. If unit 5's host starts the two turns in an order different from the recording, the fake plays the wrong thread's turn. Extend `match` to nested keys only when unit 5 needs it.
- **`early` merges "silent" with "closed".** `replay.rs:450-451` uses `.ok().flatten()`, so a stream that closes, for example because the fake crashed, reads as silence. The test still fails, at the next `next` (`"the event stream is open"`), so this is not a false green. It is noted only because the helper's `None` has two meanings.
- **`pace` has no test.** Unit 7 is its first consumer, and its behaviour is a delay that only a browser shows. Three lines with no test are acceptable until then.

## Friction points

1. **No array binding in `let`.** The subset can already express this. 0015(c) allows `let asked = Vec::from([next(..).await, ..]);` because the array is a call argument, and `Vec<String> == [&str; 3]` compares. Both ways of naming the phase are longer than the implementer's inline form, though. **Decision:** the inline form stays. No construct is needed. Naming the phase isn't worth 10 to 20 tokens when the doc line above each `send_user` or `respond` call already states the phase.
2. **Three `next(&mut events).await` per phase.** A `take(events, n)` helper over `n0_future::stream::unfold` is in the subset, since `unfold` is an allowed closure site. It is longer at two call sites, and it adds a boundary-tier stream adapter to a test. **Decision:** the repetition stays. Two sites of three calls each is below quality 7's table floor of 4 cases.
