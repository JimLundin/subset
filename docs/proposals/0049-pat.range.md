# Select an interval with a pattern

## Rule

Integer, byte, and character range patterns are allowed in every pattern
position Rust accepts. Bounds are literals or constant paths. Forms include
`1..=3`, `1..3`, `4..`, `..3`, `..=3`, `-3..=3`, and `'a'..='z'`.
An immutable `@` binding, grouping, alternatives, and nested tuple, struct,
and slice patterns keep their existing rules:

```rust
match attempts {
    0 => AttemptState::Fresh,
    1..=3 => AttemptState::Retrying,
    4.. => AttemptState::Exhausted,
}

match value {
    n @ (-3..=3) => Some(n),
    _ => None,
}

match bytes {
    [0x10..=0x1f, remaining @ ..] => Some(remaining.to_vec()),
    _ => None,
}
```

Rust checks endpoint typing, nonempty ranges, exhaustiveness, and
refutability. A signed input needs its negative cases too. A range in a
binding or parameter must cover the entire input type; for `u8`,
`let n @ 0..=255 = value;` is irrefutable and `let n @ 1..=3 = value;` is not.
An open-ended slice element must be grouped, as in `[(4..), ..]`, to
distinguish it from the slice's rest.

Boolean and floating-point ranges remain outside this rule. Range
expressions keep their existing rules: admitting `pat.range` does not
admit `let range = 1..=3;`, indexing, runtime endpoint computations,
boolean patterns, or comparisons outside predicates/guards.

## Before and after

Conductor #5 reports a desired `(1.., true, ..)` pattern in `s1.rs`.
The report's original round source was not retained. Ranges remove one
of its blockers; its comparison and boolean pattern need separate rules.
This proposal does not claim that the entire reported example is admitted.

The owner requested patterns and strong modelling beyond those examples,
then approved proceeding with Astra's first scope in #6. An isolated
example replaces membership converted through `Option`:

```rust
match attempts {
    0 => AttemptState::Fresh,
    _ => match std::ops::RangeInclusive::new(1, 3)
        .contains(&attempts)
        .then_some(AttemptState::Retrying)
    {
        Some(state) => state,
        None => AttemptState::Exhausted,
    },
}
```

with the exhaustive three-arm pattern above. The exact illustrative
before/after sources and measurements are in
[0049-ranges](0049-ranges/measurements.json). They are not Conductor source
or a project-wide savings claim. Reproduce them after `cargo build` with
`python3 docs/proposals/0049-ranges/measure.py`.

| Isolated example | Before score / tokens / lines | After score / tokens / lines |
|---|---|---|
| `classify` | 57.5 / 68 / 12 | 33.5 / 43 / 7 |
| `letter` | 21.5 / 21 / 3 | 30.5 / 41 / 6 |
| Whole illustrative file | 83.5 / 98 / 20 | 68.5 / 93 / 18 |

The interval classification saves 41.7% in score. The character pattern
costs 9.0 more points than the existing ASCII query: keep the ASCII query
when that property is the intended meaning; use character ranges for
custom intervals. The retained evidence includes this growing alternative.

## Weight

**Encouraged, 0.5**, matching literal and structural patterns. The bounds
are counted as pattern literals or constant paths, rather than expression
values. Existing boundary scoring applies; the new pattern has no special
boundary exception.

## Guard fallback coverage

A guarded range still needs a later unguarded arm that covers it:

```rust
match value {
    n @ 1..=3 if n == expected => Some(n),
    0..=4 => None,
    _ => None,
}
```

The checker orders literal bounds, respects inclusive/exclusive upper
endpoints, and recognizes missing lower or upper bounds. This also works
inside existing tuple, struct, and slice fallback checks. `1..3` does not
cover guarded `1..=3`, and `2..=4` does not cover guarded `1..=3`.

Identical constant-bound ranges are recognized structurally. Different
constant names, arithmetic equivalences such as `1..4` versus `1..=3`,
and literal integers beyond `i128` are conservatively treated as unknown
containment. Repeat the guarded range without its guard, or use a plain
binding/`_` fallback. Coverage split across several arms retains 0040's
existing conservative restriction.

## Enforcement and limits

The walker distinguishes range endpoints from expressions, so signed
literal patterns do not add unary negation to expression syntax. It
checks range attributes and visits literal/path bounds under their normal
pattern rules. The shape rule rejects direct float, boolean, and string
bounds.

The checker has no type or constant resolution. Constant endpoints must
resolve to integers or characters by review. Rust can compile float
constant ranges, so compiler success alone does not enforce this subset
restriction. Unknown constant types and aliases are the same name-resolution
limit as the existing constant-pattern rules; no constant evaluator is
introduced here.

Regression fixtures cover numeric, character and byte forms, signed and
wide unsigned bounds, nested/grouped patterns, irrefutable bindings and
parameters, and covering/noncovering guarded fallbacks. Rust compilation
tests prove the positive forms compile and reject missing signed cases,
missing guarded fallbacks, refutable bindings/parameters, and string
constant ranges. Existing array, `@`, closure and expression-range tests
remain part of the full suite.

## Qualities

1. **Named states: kept.** Intervals select named states and validated values.
2. **Visible branching: kept.** Bounds and otherwise cases appear in arms.
3. **Forward data flow: kept.** No mutation or mutable pattern forms are added.
4. **Errors are values: kept.** Unaccepted values have explicit cases.
5. **Local reasoning: kept.** The interval appears at its branch; constants
   retain Rust's resolution rules and the documented review limit.
6. **One way: kept.** Literal interval selection uses a pattern; runtime
   comparisons remain guards and iteration keeps its existing form.
7. **Repetition is data: kept.** Nested patterns select related cases
   without repeated membership conversions.

## Owner decision

The owner requested proceeding after Astra ranked range patterns first
in #6. Implemented and documented as version 13 on 2026-11-13. Fixed-size
domain arrays, borrowed slice outputs, typed identities, reference/rest
patterns, and boundary changes are subsequently implemented in version
14 under 0050–0057. Boolean ranges and range expressions retain their limits.
