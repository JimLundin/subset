# `PartialOrd` and `Ord` derives on an ordered newtype

## Rule
A newtype struct whose order is part of the domain, such as a sequence number or cursor (`HostSeq`), may derive `PartialOrd` and `Ord` alongside `PartialEq` and `Eq`. Code compares two values of it with `a.cmp(&b)` and matches the `Ordering`. It never reaches into `.0` to compare. Enums and structs with more than one field don't derive these, and IDs whose order means nothing (`CommandId`, `RequestId`) don't either.

This reverses the `PartialOrd`/`Ord` part of the bootstrap review's §A14 and the `.0.cmp(&head.0)` in `examples.md` §3. §A14 counted one derive site. It didn't count the comparisons that the derive made free, and the proto rewrite moves those comparisons into `client` and `daemon`.

## Before
`crates/proto/src/lib.rs:27` as rewritten, and the six comparisons of two `HostSeq`s in the workspace, written in the subset. The sites are `client/examples/headless.rs:102`, `daemon/src/host.rs:138`, `client/src/link.rs:319`, `link.rs:459`, `link.rs:469` and `daemon/src/server.rs:225`. Each is today an operator on `.0`, which the rewrite of those crates turns into a matched `cmp`.

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(transparent)]
pub struct HostSeq(pub u64);

fn ours(event: &Event, after: HostSeq) -> Ours {
    match event.seq.0.cmp(&after.0) {
        Ordering::Greater => Ours::Yes,
        Ordering::Less | Ordering::Equal => Ours::No,
    }
}
fn replay(log: &[Event], after_seq: HostSeq) -> Vec<Event> {
    log.iter()
        .filter_map(|e| match e.seq.0.cmp(&after_seq.0) {
            Ordering::Greater => Some(e.clone()),
            Ordering::Less | Ordering::Equal => None,
        })
        .collect()
}
fn caught_up(live_at: HostSeq, cursor: HostSeq) -> Progress {
    match live_at.0.cmp(&cursor.0) {
        Ordering::Less | Ordering::Equal => Progress::Live,
        Ordering::Greater => Progress::CatchingUp,
    }
}
fn seen(event: &Event, cursor: HostSeq) -> Seen {
    match event.seq.0.cmp(&cursor.0) {
        Ordering::Less | Ordering::Equal => Seen::Duplicate,
        Ordering::Greater => Seen::New,
    }
}
fn reached(event: &Event, live_at: HostSeq) -> Progress {
    match event.seq.0.cmp(&live_at.0) {
        Ordering::Less => Progress::CatchingUp,
        Ordering::Equal | Ordering::Greater => Progress::Live,
    }
}
fn forward(event: &Event, last: HostSeq) -> Seen {
    match event.seq.0.cmp(&last.0) {
        Ordering::Less | Ordering::Equal => Seen::Duplicate,
        Ordering::Greater => Seen::New,
    }
}
```

## After

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord, Serialize, Deserialize)]
#[serde(transparent)]
pub struct HostSeq(pub u64);

fn ours(event: &Event, after: HostSeq) -> Ours {
    match event.seq.cmp(&after) {
        Ordering::Greater => Ours::Yes,
        Ordering::Less | Ordering::Equal => Ours::No,
    }
}

## Qualities
1. Named states: kept, and helped. Callers stop unwrapping the newtype to compare, so `HostSeq` is used as a whole value.
2. Visible branching: kept. Comparison is still `cmp` and a matched `Ordering`. The operators stay out, so `<` on a `HostSeq` is still reported as `expr.binary.lt`.
3. Forward data flow: kept.
4. Errors are values: kept.
5. Local reasoning: kept. A derived order on a one-field newtype is the order of its field, which the reader sees in the struct.
6. One way: kept. Ordered newtypes compare with `cmp` like any std ordered type. The `.0.cmp(&x.0)` form goes, and `examples.md` §3 changes to `self.cmp(&head)`.

## Tool change
`tools/subset` needs a shape rule: `attr.derive` with `PartialOrd` or `Ord` only on an `item.struct.newtype`. Whether the order means something stays a review check.
