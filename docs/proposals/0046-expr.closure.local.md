# A helper used in one block can be a local closure

## Rule

An immutable `let name = |args| body;` may replace a helper whose callers
are all in that block. The binding is a plain name, without `mut`, `ref`,
a subpattern, a type annotation on the binding, or `else`. Parentheses
around the closure are allowed. Its body and captures obey the existing
subset rules; `move` does not change those rules.

There is at least one use. Every use is either a direct call, or a direct
argument, by value or shared reference, of a call that already permits
closures: a method in `closure_methods` or `predicate_adapters`, or
`Closure::new`, `unfold`, `ask`, `use_signal`, `use_future`, or `use_hook`.
Nested synchronous scopes are part of the block. Returning, storing,
aliasing, mutably borrowing, or capturing the helper in another closure
or async block is not allowed.

A plain immutable closure parameter may have a type annotation when Rust
cannot infer it, as in `|params: &Value| ...`. This admits `pat.type` only
on such a parameter of a confined local closure. The type itself still
obeys the subset: `bool`, lifetimes, and `impl Trait` do not gain new
positions. Type annotations on local bindings remain outside.

Boolean expressions still belong to an inline predicate closure or a
permitted match guard. A named predicate does not gain that exception.
Async blocks retain 0006's inline positions. This proposal does not add
`from_fn`, `spawn_blocking`, closures in signatures, or new callback
methods. Those requests in issue #5 need their own cases.

A shape shared across functions stays a free function. The local form is
for sharing inside one block, not for copying a shared function into each
caller. This distinction is a review check.

## Weight

**Tolerated, 2.0.** `expr.closure` keeps its existing tier. A local helper
has inferred capture and parameter types, so its call has more implicit
context than a free function's signature. `pat.type` is also tolerated:
it restores an input type when inference needs it, without admitting
annotated bindings generally.

Boundary use does not apply to the local closure declaration. Passing it
to a library does not make its definition a boundary node. Its body keeps
the normal scoring of its calls and values. The measurements use version
11's weights directly; no outside weight is left to reprice.

## Qualities

1. **Named states: kept.** Closures build the same structs and variants;
   no boolean state or sentinel is introduced.
2. **Visible branching: kept.** Every construct inside the closure keeps
   its existing rule; predicates and async bodies stay inline.
3. **Forward data flow: kept.** The binding is immutable. Capture does not
   admit new mutation, assignment, or mutable-reference positions.
4. **Errors are values: kept.** The error mappings return the same errors;
   `Result` and `?` are unchanged.
5. **Local reasoning: kept.** The helper and all its references are in one
   lexical block. Parameter annotations restore types where needed, and
   captures cannot be forwarded to another closure or async task.
6. **One way: kept.** Share a block-local shape with a local helper; share
   a shape across functions with a free function. No general callbacks
   or closure signatures are admitted.
7. **Repetition is data: kept.** Each block's shape is written once. The
   unfavorable cross-test rewrites are excluded by the shared-function
   rule, and tables keep their existing rules.

## Tool change and limits

The checker analyzes a block-local binding's later references, including
local, arm, loop, closure-parameter and nested-item shadowing. It permits
only direct invocation or arguments of the existing closure-taking calls,
and rejects references inside another closure or async block. The
accepted closure is still `expr.closure`, so its existing tier applies.
Only its plain typed parameters get the new `pat.type` position.

Expression arguments of the standard `assert_eq!`, `assert_ne!`,
`format!`, `write!`, and `writeln!` macros are parsed to check references;
implicit format-string capture is a stored-value use. Unrecognized macro
references are rejected conservatively. Macros are not expanded, and
callee names are checked against the same lists as inline closures; Rust
name resolution and whether a library retains a callback remain review
checks. A configured method name is not proof of its behavior.

Not measured: other crates, the UI button handler, channel draining,
blocking locks, or closure-returning signatures. The report's original
round commits were not available in its body. Current cross-function
helpers were measured as unfavorable alternatives, not proposed rewrites.
