# The actor loop

## Rule
`loop` is allowed only as the whole body of (a) an actor's `run` function or (b) a function that drives one source until a terminal value. The loop body takes the next input in one statement or expression: a `tokio::select!`, a `match` on the actor's state whose arms are `select!`s, or one awaited receive. It then handles the input with one call or one `match`. Each `select!` arm is a single call of a method or a variant constructor. Logic stays in the methods, where the checker can see it. The loop ends only through `?` (an actor's `run` returns `Result<Infallible, E>`) or through `break value` in a drive function. `while`, `while let`, `for` with `.await` in its body, and `continue` are not allowed. They become this shape or iterator adapters (see the review's §A6).

## Before
The current loop in `crates/agents/src/claude/session.rs`, `Actor::run`. It is outside the subset: `let … else`, `return`, `continue`. No subset-only form of a multi-source wait exists, because `select!` and `loop` are the only way to wait on several sources whose deadlines depend on state (the str0m driver in `crates/daemon/src/rtc.rs` recomputes its timer every turn).

```rust
impl Actor {
    async fn run(mut self, mut commands: mpsc::Receiver<CommandMsg>) {
        loop {
            let Process::Running(running) = &mut self.process else {
                let Some(cmd) = commands.recv().await else {
                    return;
                };
                self.on_command(cmd).await;
                continue;
            };
            tokio::select! {
                line = running.stdout.next_line() => match line {
                    Ok(Some(line)) => self.on_line(&line).await,
                    Ok(None) => {
                        self.stop().await;
                    }
                    Err(e) => {
                        tracing::error!("reading claude stdout: {e}");
                        self.stop().await;
                    }
                },
                cmd = commands.recv() => match cmd {
                    Some(cmd) => self.on_command(cmd).await,
                    None => {
                        self.stop().await;
                        return;
                    }
                },
            }
        }
    }
}
```

## After
The same actor in the rule's shape. Stdout and command handling move to methods, so `run` holds no logic.

```rust
/// The command channel closed: nobody can talk to the actor any more.
struct Stopped {}

impl Actor {
    async fn run(mut self, mut commands: mpsc::Receiver<CommandMsg>) -> Result<Infallible, Stopped> {
        loop {
            match &mut self.process {
                Process::Running(running) => tokio::select! {
                    line = running.stdout.next_line() => self.on_stdout(line).await,
                    cmd = commands.recv() => self.on_command(cmd).await?,
                },
                Process::Exited(_) => self.on_command(commands.recv().await).await?,
            }
        }
    }

    async fn on_stdout(&mut self, line: std::io::Result<Option<String>>) {
        match line {
            Ok(Some(line)) => self.on_line(&line).await,
            Ok(None) => {
                self.stop().await;
            }
            Err(e) => {
                tracing::error!("reading claude stdout: {e}");
                self.stop().await;
            }
        }
    }

    async fn on_command(&mut self, cmd: Option<CommandMsg>) -> Result<(), Stopped> {
        match cmd {
            Some(cmd) => {
                self.on_message(cmd).await;
                Ok(())
            }
            None => {
                self.stop().await;
                Err(Stopped {})
            }
        }
    }
}
```

## Measurements

|---|---|---|
| before | 173 | 32 |
| after | 248 | 38 |
| change | +75 (+43%) | +6 (+19%) |

The rule costs 43% more tokens than today's free-form loop. That is the price of one exit (`?`) instead of `return` and `continue` scattered through arms. It buys `run` functions that read alike across actors. The before column is not subset code, so this is not a ratchet saving. The proposal rests on necessity, and the number is the rule's cost against the unconstrained form.

Friction points removed: 35 sites: 23 `expr.loop`, 9 `macro.tokio::select` and 3 `expr.break`. The rule's shape also replaces the 20 `expr.while`/`expr.while_let` loops. `crates/client/src/link.rs` already uses this shape (`let step = tokio::select! { … => Step::Frame(…) }`, then `match step`), so the rule writes down existing practice.

## Qualities
1. Named states: kept. The input is a variant of a named enum or a typed method argument.
2. Visible branching: kept. Each `select!` arm is one call. The decision is a `match` in a method, where the checker sees it.
3. Forward data flow: kept within the loop. The actor's state changes only under proposal 0008.
4. Errors are values: kept, and helped. The actor ends by returning an error value through `?`, which its spawner can match.
5. Local reasoning: kept. Every actor's `run` reads the same: take the next input, hand it to a method.
6. One way: kept. One loop shape for actors and drive functions.
