# A method call as the base of a struct update

## Rule
Amends 0004(a). The base of `..base` may also be a method call that returns a fresh value of the struct's own type, such as `..self.outbox.current()`. When the base is used once, write the call in place rather than binding it first. Everything else in 0004 stays.

## Before
`crates/client/src/link.rs`, nine sites (`:487`, `:542`, `:562`, `:595`, `:607`, `:636`, `:696`, `:709`, `:720`). 0004 accepts only a path or a constructor call as the base, so each site binds the current status first.

```rust
let current = self.outbox.current();
self.outbox
    .publish(Status {
        host: Some(welcome.host.clone()),
        state: LinkState::CatchingUp,
        ..current
    })
    .await?;
```

## After
```rust
self.outbox
    .publish(Status {
        host: Some(welcome.host.clone()),
        state: LinkState::CatchingUp,
        ..self.outbox.current()
    })
    .await?;
```

Scratch files: `docs/subset/measurements/client-review/0036/before.rs` (the file at `4a29f1f`) and `after.rs` (all nine sites rewritten, formatted with rustfmt).

## Qualities
1. Named states: kept. The fields named are still the ones that change.
2. Visible branching: kept. No control flow.
3. Forward data flow: kept. The base is a new value, built where it is used.
4. Errors are values: kept.
5. Local reasoning: kept. The base's type is the struct's type, as in 0004(a), and the call that makes it sits in the expression.
6. One way: kept. The rule says when to bind and when not: a base used once is written in place.
7. Repetition is data: kept, and helped. Nine copies of `let current = …;` go. The rest of each site differs in its fields, so it stays.
