# wasm-bindgen callbacks

## Rule
`dyn` is allowed only as `Closure<dyn FnMut(..)>` from `wasm_bindgen::closure`, in `crates/client/src/platform/`. A closure that is not a method argument (`expr.closure`) is allowed only as the argument of `Closure::new`. Its body forwards the browser event into a channel as a named message, and does nothing else. Decisions about that message are made by the actor that receives it. A boxed future is written `n0_future::boxed::BoxFuture<T>`, not `Pin<Box<dyn Future<…>>>` (§A11).

## Before
No subset-only form exists. The browser calls Rust back only through a JavaScript function, and wasm-bindgen builds one only from `Closure<dyn FnMut(..)>`.

## After
```rust
// crates/client/src/platform/rtc.rs, rewritten to the rule
let on_state = Closure::<dyn FnMut()>::new({
    let pc = pc.clone();
    let events = events.clone();
    move || drop(events.send(PeerEvent::State(pc.connection_state())))
});
pc.set_onconnectionstatechange(Some(on_state.as_ref().unchecked_ref()));
```

Not measured: there is no version without the construct. The proposal rests on necessity.

Friction points removed: 12 `type.dyn` sites in 2 files. 10 are wasm-bindgen closures; the 2 in `crates/client/src/upgrade.rs` become `BoxFuture`. Of the 39 `expr.closure` sites, 5 are `Closure::new` arguments. The other 5 in `platform/rtc.rs` are local helpers, which become named functions (§A8).

## Qualities
1. Named states: kept, and helped. Browser events arrive as variants of a named enum.
2. Visible branching: kept. The rule moves today's `if matches!(state, …)` and `let … else { return }` out of the callbacks and into the actor's `match`.
3. Forward data flow: kept, and helped. Callbacks no longer write to `Rc<RefCell<…>>` or `watch::Sender<bool>`. Today's code does both, and it is interior mutability, which the subset rules out (see the review's tool gaps).
4. Errors are values: kept.
5. Local reasoning: kept. The callback's text is one line.
6. One way: kept. One way into Rust from the browser.
