# Error enums derive `thiserror::Error`

## Rule
`#[derive(thiserror::Error)]` is allowed on an enum, or a struct with named fields, whose name ends in `Error` or that is used only as the `E` of a `Result`. Each variant carries one `#[error("…")]` with a message. `#[error(transparent)]` and `#[source]` are not part of this proposal. `#[from]` is proposal 0011.

## Before
The long-hand form: `Display` and `std::error::Error` written by hand for `crates/agents/src/claude/session.rs` `Error`. This form needs trait impls outside 0009's list, so the subset can't express it either. A subset-only error enum would have only `Debug`. It could not be used with `anyhow` in the bins, or shown to a user.

```rust
#[derive(Debug)]
pub enum Error {
    Command(String),
    Io(std::io::Error),
    Encode(serde_json::Error),
    Exited,
    Control { subtype: String, message: String },
    Timeout(String),
    UnsupportedVersion { found: String, supported: String },
    UnknownPermissionRequest(PermissionRequestId),
}

impl std::fmt::Display for Error {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            Error::Command(e) => write!(f, "could not build the claude command: {e}"),
            Error::Io(e) => write!(f, "claude i/o: {e}"),
            Error::Encode(e) => write!(f, "could not encode a message for claude: {e}"),
            Error::Exited => write!(f, "the claude process has exited"),
            Error::Control { subtype, message } => write!(f, "claude rejected {subtype}: {message}"),
            Error::Timeout(call) => write!(f, "claude did not answer {call} within {CONTROL_TIMEOUT:?}"),
            Error::UnsupportedVersion { found, supported } => write!(
                f,
                "claude {found} is not supported (supported: {supported}); set allow_untested_version to run it anyway"
            ),
            Error::UnknownPermissionRequest(id) => {
                write!(f, "no open permission request with id {}", id.text())
            }
        }
    }
}

impl std::error::Error for Error {
    fn source(&self) -> Option<&(dyn std::error::Error + 'static)> {
        match self {
            Error::Io(e) => Some(e),
            Error::Encode(e) => Some(e),
            _ => None,
        }
    }
}
```

## After
```rust
#[derive(Debug, thiserror::Error)]
pub enum Error {
    #[error("could not build the claude command: {0}")]
    Command(String),
    #[error("claude i/o: {0}")]
    Io(std::io::Error),
    #[error("could not encode a message for claude: {0}")]
    Encode(serde_json::Error),
    #[error("the claude process has exited")]
    Exited,
    #[error("claude rejected {subtype}: {message}")]
    Control { subtype: String, message: String },
    #[error("claude did not answer {0} within {CONTROL_TIMEOUT:?}")]
    Timeout(String),
    #[error("claude {found} is not supported (supported: {supported}); set allow_untested_version to run it anyway")]
    UnsupportedVersion { found: String, supported: String },
    #[error("no open permission request with id {}", .0.text())]
    UnknownPermissionRequest(PermissionRequestId),
}
```

## Qualities
1. Named states: kept. Each failure is still a named variant.
2. Visible branching: kept. The derive generates a `match` over the variants. It adds no branching to our code.
3. Forward data flow: kept.
4. Errors are values: kept, and helped. Errors become real `std::error::Error` values that `anyhow` and the UI can show.
5. Local reasoning: kept. The message sits on the variant it describes.
6. One way: kept. One way to give an error a message.
