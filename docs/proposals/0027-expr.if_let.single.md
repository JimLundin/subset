# `if let` with one branch

## Rule
`if let Pattern = expr { … }` is allowed only with no `else`, no `else if` and no `&&` let-chain. It is the one form for "act only on this case". Anything with an alternative branch stays a `match`, with every arm written out.

The checker gives this form its own id, `expr.if_let.single`. An `if let` with an `else` or an `else if` is still `expr.if_let`, and a let-chain is still `expr.if` with `expr.let` and `expr.binary.and`. None of those are allowed.

A `match` whose only other arm is `None => {}` or `_ => {}` is the shape this replaces. clippy's `single_match` already rejects it, and with 0025 revised no lint is switched off, so clippy and the subset agree on the one form.

## Before
`crates/agents/src/codex/server.rs:410-419` as the agents rewrite wrote it. The `trace!` arm exists only to give the `match` a second arm, which `single_match` would otherwise reject.

```rust
match self.open.remove(&id) {
    Some(_) => {
        self.emit(CodexEvent::Thread { thread, event: ThreadEvent::ApprovalCancelled { id } }).await;
    }
    None => tracing::trace!("codex resolved {}, which we answered", id.0),
}
```

## After
```rust
if let Some(Open { .. }) = self.open.remove(&id) {
    self.emit(CodexEvent::Thread { thread, event: ThreadEvent::ApprovalCancelled { id } }).await;
}
```

The pattern names the payload with its fields elided, `Some(Open { .. })`. An earlier version of this section wrote `Some(_)`, which fails clippy's `redundant_pattern_matching`. `Some(..)` fails it too, and is `pat.rest`, which the subset doesn't allow (`docs/subset/reviews/v4-agents-proto.md`, friction 1). A payload with no struct or tuple-struct pattern, such as a `String`, has no form for this yet; log it as friction when one turns up.

## Measurements
0025 measured the two `single_match` sites with a padding-free `match` at -11.9% (252 to 222 tokens). The `if let` form drops the empty arm as well, so it is at least as short. This proposal rests on the owner's decision to keep every default lint on, not on the volume.

## Qualities
1. Named states: kept. The pattern still names the variant.
2. Visible branching: kept. There is one branch and nothing hides behind it. A second branch needs a `match`, so a reader never meets a two-way decision written as `if let … else`.
3. Forward data flow: kept.
4. Errors are values: kept.
5. Local reasoning: kept.
6. One way: kept. "Act only on this case" has one form. With an `else` the form is forbidden, so the choice between `if let` and `match` is decided by the number of branches, not by taste.
