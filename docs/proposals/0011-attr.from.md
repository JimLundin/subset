# `#[from]` on error variants

## Rule
`#[from]` is allowed on a `thiserror` variant (0010) that wraps another error type, ours or a library's, when that variant is the only one in the enum holding that type. (Amended 2026-11-11: the owner extended it to our own error types.) `?` then converts it. Where one source type means different things in one enum, use `map_err` with the variant constructor, as in `examples.md` §7.

## Before
Explicit `map_err` at each `?`, from `crates/agents/src/claude/session.rs` (`write` and the stdout-log open in `spawn`):

```rust
async fn write(&mut self, msg: Outbound) -> Result<(), Error> {
    let running = self.running()?;
    let line = encode(msg).map_err(Error::Encode)?;
    running.stdin.write_all(line.as_bytes()).await.map_err(Error::Io)?;
    running.stdin.flush().await.map_err(Error::Io)?;
    Ok(())
}
fn stdout_log(opts: &ClaudeOptions) -> Result<Option<std::fs::File>, Error> {
    match &opts.stdout_log {
        Some(path) => Ok(Some(std::fs::OpenOptions::new().create(true).append(true).open(path).map_err(Error::Io)?)),
        None => Ok(None),
    }
}
```

## After
```rust
async fn write(&mut self, msg: Outbound) -> Result<(), Error> {
    let running = self.running()?;
    let line = encode(msg)?;
    running.stdin.write_all(line.as_bytes()).await?;
    running.stdin.flush().await?;
    Ok(())
}
fn stdout_log(opts: &ClaudeOptions) -> Result<Option<std::fs::File>, Error> {
    match &opts.stdout_log {
        Some(path) => Ok(Some(std::fs::OpenOptions::new().create(true).append(true).open(path)?)),
        None => Ok(None),
    }
}
```

Friction points removed: 21 sites of `attr.from` in 7 files. Each covers every `?` on that source type in the module. `session.rs` alone has 6 such `?`s.

The reviewer's recommendation is to accept this only after 0010. It is a separate proposal so the owner can keep `examples.md` §7's explicit style and still take 0010.

## Qualities
1. Named states: kept. The source error lands in a named variant.
2. Visible branching: kept. `?` is the core's one early exit. The conversion doesn't add a branch.
3. Forward data flow: kept.
4. Errors are values: kept.
5. Local reasoning: weakened slightly. The conversion target is not written at the `?`. The reader finds it on the error type named in the signature, which is the narrowest place it could be. The one-variant-per-source rule means there is never a choice to look up.
6. One way: at risk, and limited by the rule. Two idioms exist (`?` alone and `map_err`). The rule picks between them by a fact about the enum, not by taste.

## Owner decision
Accepted on 2026-11-11, with the rest of the bootstrap round.
