# `pub` visibility

## Rule
`pub` marks an item, field or re-export that another crate uses. A crate's API is its `pub` items reachable from the crate root, usually through `pub use` in `lib.rs` or a module's `mod.rs`. Inside a crate, items shared between modules use `pub(crate)` (proposal 0003).

## Before
No subset-only form exists. Without `pub`, no crate can call another: `client` cannot use `proto::HostSeq`, and `daemon` cannot use `agents`. The workspace is seven crates (`docs/architecture.md` §6), so every crate boundary needs it.

## After
```rust
// crates/agents/src/claude/mod.rs
mod protocol;
mod session;

pub use protocol::{
    Block, ClaudeEvent, PermissionDecision, PermissionMode, PermissionRequestId, Role, SessionId,
};
pub use session::{ClaudeOptions, ClaudeSession, Error, Result, SettingSource};

// crates/proto/src/lib.rs
pub struct HostSeq(pub u64);
```

## Qualities
1. Named states: kept. Visibility says who may use an item, not what state a value is in.
2. Visible branching: kept. No control flow.
3. Forward data flow: kept. `pub` fields can be read from outside. Changing them still needs `mut`, which the rules control separately.
4. Errors are values: kept.
5. Local reasoning: kept, and helped. The `pub use` list at a module root says what the module offers.
6. One way: kept, given 0003. Then `pub` always means "leaves the crate".
