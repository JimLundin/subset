# `&mut self` on stream endpoints of ours

## Rule
A type of ours on the `endpoints` list in `subset.toml` may have methods that take `&mut self`, and code anywhere may call them on a `let mut` binding, a `mut` pattern or a field. The list starts as `SendHalf`, `RecvHalf`, `ChannelRecv` and `FrameBuffer`. A type joins it by review: it wraps a library stream or channel whose own API takes `&mut` (0008(b)), or it is the reassembly buffer of one. Every other rule of 0008 stays: no `&mut` parameter of our types, no compound assignment, no interior mutability. Data types keep their value-returning methods.

This extends 0008(b), "external values whose API takes `&mut`", to our thin wrappers of those values. It does not extend 0008(a).

## Before
`crates/client/src/wire.rs:67-138` at `4a29f1f`. Every read and write takes its half and hands it back, so each path returns the stream as well as the result.

```rust

    pub async fn read<T: DeserializeOwned>(self) -> (RecvHalf, Result<Option<T>, WireError>) {

            Self::Iroh(recv) => {
                let (recv, body) = read_iroh(recv).await;

            }
            Self::WebRtc(recv) => {
```

The callers rebind every half (`let send = send.write(..).await?`, `let _send = send.finish()?`, `let (_recv, reply) = recv.read().await`). `ChannelRecv::read_body` (`rtc.rs:628-687`) threads itself through `ReadStep::{Done(ChannelRecv, ..), More(ChannelRecv)}` with a struct update per message, and `Signaling::send` (`rtc.rs:372-380`) takes the host out with `std::mem::replace` to write and puts it back. `proto::FrameBuffer` returns `Reassembly::Frame { body, rest }` so its caller can swap the rest back in.

## After
```rust
impl SendHalf {
    pub async fn write<T: Serialize>(&mut self, msg: &T) -> Result<(), WireError> {
        let frame = proto::encode(msg)?;
        match self {
            Self::Iroh(send) => send.write_all(&frame).await?,
            Self::WebRtc(send) => send.write(&frame).map_err(WireError::Channel)?,
        }
        Ok(())
    }
}

impl RecvHalf {
    pub async fn read<T: DeserializeOwned>(&mut self) -> Result<Option<T>, WireError> {
        let body = match self {
            Self::Iroh(recv) => read_iroh(recv).await?,
            Self::WebRtc(recv) => recv.read_body().await?,
        };
        Ok(body.map(|body| proto::decode(&body)).transpose()?)
    }
}

async fn rpc(carrier: Transport, command: Command) -> Result<CommandResult, SendError> {
    let (mut send, mut recv) = carrier.open_bi().await?;
    send.write(&Open::Command(command)).await?;
    send.finish()?;
    recv.read().await?.ok_or(SendError::NoResult)
}

// Signaling::send writes in place, with no swap:
if let Host::Up { send, .. } = &mut self.host {
    let written = send.write(&signal).await;
    if let Err(err) = written {
        self.ended(err.to_string());
    }
}
```

## Weight
costly. It is mutation, the same tier as 0008. Boundary use: doesn't apply. Our wrapper's signature is ours to choose; the library fixes only the `&mut` of the value inside, which 0008(b) already covers.

## Qualities
1. Named states: kept. `ReadStep::{Done, More}` stays as the reader's step. `Reassembly` goes, but it named "here is the rest of me", not a state of the stream.
2. Visible branching: kept. Every branch is still a `match` or a single `if let`.
3. Forward data flow: weakened, but only where it was already a fiction. The state of a stream (bytes consumed, the peer's window) lives outside the program. Returning the half by value didn't make that state flow forward. It only made every caller thread the handle back. 0008(b) already accepts this for the library value inside. Data types keep value-returning methods.
4. Errors are values: kept, and helped. Today a write error drops the half (`Result<SendHalf, _>`). With `&mut`, the caller keeps the stream and decides. `read` returns a plain `Result` instead of a `(RecvHalf, Result)` pair.
5. Local reasoning: kept. The `&mut self` in the signature and the `mut` at the binding say where the stream changes. `&mut` is exclusive, so nothing else sees it change.
6. One way: kept, and helped. Today stream I/O has two idioms: `&mut` for library streams and by-value for ours. The list makes it one idiom for every stream. A type that is not on the list has one idiom too.
7. Repetition is data: kept. The hand-back arm that every read path repeated (`(Self::Iroh(recv), body)`, `(recv, Err(err.into()))`) goes.
