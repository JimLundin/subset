# Platform `cfg` attributes

## Rule
`#[cfg(...)]` is allowed with exactly these predicates: `target_family = "wasm"`, `not(target_family = "wasm")`, `unix` and `not(unix)`. It may sit on a `mod`, `use`, `fn` or `impl` item, and as `#![cfg(unix)]` at the top of a test file. Each `cfg` item must have its counterpart for the other platform in the same file, unless it is a test file or a module that exists on one platform only (`platform/rtc.rs`). `cfg` on statements or expressions is not allowed. Feature flags need their own proposal.

## Before
No subset-only form exists. The `client` crate compiles natively and to `wasm32-unknown-unknown` (`docs/architecture.md` §9). Only `cfg` keeps the browser's WebRTC code out of the native build and the native iroh endpoint out of the browser.

## After
```rust
// crates/client/src/platform/mod.rs
#[cfg(not(target_family = "wasm"))]
mod native;
#[cfg(target_family = "wasm")]
pub(crate) mod rtc;
#[cfg(target_family = "wasm")]
mod web;

#[cfg(not(target_family = "wasm"))]
pub use native::bind_endpoint;
#[cfg(target_family = "wasm")]
pub use web::bind_endpoint;
```

Friction points removed: 30 sites of `attr.cfg` in 7 files. All of them use the four predicates above.

## Qualities
1. Named states: kept.
2. Visible branching: kept, though `cfg` is a compile-time branch. The rule keeps it at item level, in pairs, so both sides are visible next to each other.
3. Forward data flow: kept.
4. Errors are values: kept.
5. Local reasoning: kept. Each platform's code is a whole item, readable on its own.
6. One way: kept. One platform switch, at item level.
