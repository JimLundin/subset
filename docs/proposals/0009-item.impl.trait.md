# Trait impls a library requires

## Rule
`impl Trait for Type` is allowed only for a trait that a library calls our type through and that has no inherent-method equivalent. The list is: `Drop` (releasing a resource), `Debug` written by hand (to keep a secret out of logs, or for a struct holding values that have no `Debug`, such as wasm-bindgen closures), `Serialize` and `Deserialize` written by hand where a derive can't express the wire shape, and a framework's handler trait (iroh's `ProtocolHandler`). Generic parameters and lifetimes are allowed in such an impl only where the trait's own signature demands them (`impl<'de> Deserialize<'de>`, `fn serialize<S: Serializer>`, `Formatter<'_>`). `Display`, `FromStr` and `From` are not on the list. Write `fn label(&self) -> String`, `fn parse(s: &str) -> Result<Self, E>` and `fn to_cli(self) -> claude_codes::X` instead. clap takes `#[arg(value_parser = Ticket::parse)]`.

## Before
The traits the rule leaves out, as they are written today (`crates/agents/src/claude/protocol.rs`, `crates/proto/src/ticket.rs`):

```rust
impl std::fmt::Display for PermissionRequestId {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        f.write_str(&self.0)
    }
}

impl fmt::Display for AuthToken {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_str(&HEXLOWER.encode(&self.0))
    }
}

impl FromStr for AuthToken {
    type Err = TicketError;

    fn from_str(s: &str) -> Result<Self, Self::Err> {
        HEXLOWER
            .decode(s.as_bytes())
            .ok()
            .and_then(|bytes| bytes.try_into().ok())
            .map(Self)
            .ok_or(TicketError::Token)
    }
}

#[derive(Parser)]
struct Args {
    ticket: Ticket,
}

fn report(id: &PermissionRequestId, token: &AuthToken) {
    tracing::info!(%id, %token, "answered");
}
```

## After
The same behaviour with inherent methods:

```rust
impl PermissionRequestId {
    pub fn text(&self) -> &str {
        &self.0
    }
}

impl AuthToken {
    pub fn hex(&self) -> String {
        HEXLOWER.encode(&self.0)
    }

    pub fn parse(s: &str) -> Result<AuthToken, TicketError> {
        HEXLOWER
            .decode(s.as_bytes())
            .ok()
            .and_then(|bytes| bytes.try_into().ok())
            .map(AuthToken)
            .ok_or(TicketError::Token)
    }
}

#[derive(Parser)]
struct Args {
    #[arg(value_parser = Ticket::parse)]
    ticket: Ticket,
}

fn report(id: &PermissionRequestId, token: &AuthToken) {
    tracing::info!(id = id.text(), token = token.hex(), "answered");
}
```

The traits the rule keeps have no inherent form, for example `crates/daemon/src/server.rs`:

```rust
impl ProtocolHandler for Conductor {
    async fn accept(&self, conn: Connection) -> Result<(), AcceptError> { … }
}
```

## Measurements

| before | 199 | 28 |

| change | -51 (-26%) | -2 (-7%) |

Before: `Display`/`FromStr` as trait impls. After: inherent methods. The table shows why the rule leaves those traits out. For `Drop`, `ProtocolHandler` and the hand-written serde impls there is no version without the construct, and the proposal rests on necessity.

Friction points removed: 8 of the 19 `item.impl.trait` sites fit the list: 3 `Drop`, 2 hand-written `Debug`, 2 serde, 1 `ProtocolHandler`. The other 11 (5 `Display`, 2 `FromStr`, 4 `From`) are rewritten as methods (§A14). `item.impl.type` (2, the `FromStr::Err` types) goes with them.

## Qualities
1. Named states: kept.
2. Visible branching: kept.
3. Forward data flow: kept. `Drop` runs at a visible scope end. It changes nothing a reader holds.
4. Errors are values: kept. A hand-written `Deserialize` still reports errors as values.
5. Local reasoning: weakened slightly, and accepted as necessary. A trait impl is code that a library calls from elsewhere. The short list keeps the set of such entry points small and known.
6. One way: kept. Conversions and formatting each have one form, a named method.
