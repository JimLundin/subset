# Awaiting one step per item, in order, inside an actor

## Rule
A `for` loop may stand as a statement in an `async fn` that takes
`&mut self` on an actor's loop state (0008). Its body is exactly one
statement, `self.method(item).await?;`, where `item` is the loop's binding.
The loop iterates an owned collection. There is no `break`, `continue` or
other statement in the body.

This is the one form for applying a list to loop state in order, one
awaited step at a time. Elsewhere `stream::iter(..).then(..)` stays the one
form, because there its closure can borrow what it needs. Inside loop state
it can't. The closure passed to `then` would have to hold `&mut self` in an
`FnMut` across an await, which the borrow checker refuses. Today the only
v6 way round that splits the work into a synchronous state change and a
list of deferred effects (F1 in `.audit/p1-u4.friction.md`).

The rule amends 0007's sentence "`for` with `.await` in its body … not
allowed" and bootstrap review §A6's rewrite of such a `for`, for this one
shape only.

/// What a settled step leaves the actor to do, outside its own state.
enum Effect {
    Emit(EventKind),
    Interrupt,
    /// The session is over.
    End,
}

    async fn apply(&mut self, steps: Vec<Step>) -> Result<(), Stopped> {
        let effects = steps
            .into_iter()
            .flat_map(|step| self.settle(step))
            .collect::<Vec<Effect>>();
        self.perform(effects).await
    }

    async fn perform(&self, effects: Vec<Effect>) -> Result<(), Stopped> {
        n0_future::stream::iter(effects)
            .then(|effect| self.effect(effect))
            .try_collect()
            .await
    }

    fn settle(&mut self, step: Step) -> Vec<Effect> {
        match step {
            Step::Emit(kind) => Vec::from([Effect::Emit(kind)]),
            // .. Open, ToolFinished, TurnEnded: change state, return Vec::from([Effect::Emit(..)])
            Step::Withdraw(native) => self.withdraw(native),
            Step::TurnStarted(native) => {
                let before = std::mem::replace(&mut self.turn, Turn::Running(native));
                match before {
                    Turn::Starting(Held::Interrupt) => Vec::from([Effect::Interrupt]),
                    Turn::Starting(Held::Nothing) | Turn::Idle | Turn::Running(_) => Vec::new(),
                }
            }
            Step::Closed(reason) => Vec::from([
                Effect::Emit(EventKind::SessionClosed { reason }),
                Effect::End,
            ]),
        }
    }

    fn withdraw(&mut self, native: NativeRequest) -> Vec<Effect> { /* .. */ }

    async fn effect(&self, effect: Effect) -> Result<(), Stopped> {
        match effect {
            Effect::Emit(kind) => self.emit(kind).await,
            Effect::Interrupt => {
                let sent = self.interrupt().await;
                self.note(sent).await
            }
            Effect::End => Err(Stopped {}),
        }
    }

## After
The full file is reproduced by
`docs/subset/measurements/p1-u4/f1-after.rs`.

```rust
    /// Applies the steps in order, until one ends the session.
    async fn apply(&mut self, steps: Vec<Step>) -> Result<(), Stopped> {
        for step in steps {
            self.step(step).await?;
        }
        Ok(())
    }

    async fn step(&mut self, step: Step) -> Result<(), Stopped> {
        match step {
            Step::Emit(kind) => self.emit(kind).await,
            // .. Open, ToolFinished, TurnEnded: change state, then self.emit(..).await
            Step::Withdraw(native) => self.withdraw(native).await,
            Step::TurnStarted(native) => {
                let before = std::mem::replace(&mut self.turn, Turn::Running(native));
                match before {
                    Turn::Starting(Held::Interrupt) => {
                        let sent = self.interrupt().await;
                        self.note(sent).await
                    }
                    Turn::Starting(Held::Nothing) | Turn::Idle | Turn::Running(_) => Ok(()),
                }
            }
            Step::Closed(reason) => {
                self.emit(EventKind::SessionClosed { reason }).await?;
                Err(Stopped {})
            }
        }
    }
```

`Effect`, `perform`, `effect` and the `n0_future::StreamExt` import go.
`withdraw` emits instead of returning a `Vec<Effect>`. It compiles
(`cargo check -p daemon --tests` on the scratch copy).

## Weight
tolerated (2.0). It sequences awaits like `async`/`.await`, which are
tolerated, and it changes no binding, so it is not costly like `loop`.
Boundary use: doesn't apply. No library fixes its shape.

## Qualities
1. Named states: kept. `Effect` named deferred actions, not states. `Turn`,
   `Held` and `Pending` are unchanged.
2. Visible branching: kept. The loop adds no branch. Its only exit is `?`,
   already the subset's one early exit.
3. Forward data flow: kept. No binding changes. The loop binding is fresh
   on each pass, and mutation stays in loop state through `&mut self`, as
   0008 allows.
4. Errors are values: kept. A failed step ends the loop through `?`.
5. Local reasoning: kept, and better. Each step's state change and its
   effect sit in one arm. Before, a reader matched a `settle` arm to an
   `effect` arm through `Effect`.
6. One way: kept, with the rule's boundary drawn by the receiver. Inside
   loop state, `for` is the only form, since `then` can't borrow `&mut self`
   there. Outside it, `then` stays the only form. The owner may judge a
   receiver-keyed split a weakening. If so, the general rule measures
   -10.2% and fails the threshold.
7. Repetition is data: kept. Nothing repeats.
