# Struct update with `..base`

## Rule
`..base` in a struct expression is allowed in two cases. (a) `base` is an existing value of the same type, and the expression builds the changed copy (`examples.md` §12, `Host { name, ..host }`). (b) `base` is `Default::default()` or a named constructor (`Options::new(..)`), and the struct comes from a vendored or external crate whose omitted fields are all `Option` or empty collections.

Every field spelled out, from `crates/agents/src/codex/protocol.rs` `Call::params`, three arms:

Friction points removed: 9 sites in 4 files. The spelled-out form also breaks the build whenever `codex-codes` adds an optional field, which the generated types in `vendor/codex-codes` do on every protocol update. In the real code, 0008's measured "before" depends on case (a) to rebuild actor state without `mut`.

## Qualities
1. Named states: kept. The fields named are the ones that matter. The rest keep their documented default.
2. Visible branching: kept. No control flow.
3. Forward data flow: kept, and helped. Case (a) is how the subset changes a value without a mutable binding.
4. Errors are values: kept.
5. Local reasoning: kept. In case (a) the base's type is the struct's type. In case (b) the default is a single named constructor.
6. One way: kept. One way to say "this value, with these fields changed".
